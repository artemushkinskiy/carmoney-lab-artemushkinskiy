# Spec MILEAGE: пробег авто больше 400 000 км — решение review

ID задачи: `MILEAGE`. Источник требований: `docs/intent/intent_MILEAGE.md` (интервью Grill Me: `docs/intent/grill_MILEAGE.md`). Формат — `docs/spec/README.md`: здесь «что считается сделанным»; как реализовывать — `docs/plan/plan_MILEAGE.md`.

## 1. Входит / не входит

**Входит:**

- Проверка пробега при расчёте решения: порог 400 000 км, граница включительно, понижение approve до review — REQ-MILEAGE-01…03.
- Обязательность пробега: пустое или неизвестное значение — ошибка валидации до расчёта решения — REQ-MILEAGE-04…05.

**Не входит** (спека требований по этим пунктам не содержит):

- Причина review в ответе API: поле не добавляем, формат ответа не меняется. — intent §5.
- Поведение при LTV-reject и пробеге > 400 000 км (reject или review): не фиксируется, вопрос перенесён аналитику (OQ-1). — intent §4 п.1.
- `approved_limit` при понижении approve → review по пробегу (0 или предварительный лимит): не фиксируется, вопрос перенесён аналитику (OQ-2). — intent §4 п.2.
- Изменение действующей валидации пробега 0–500 000 км: порог `max_mileage_km` не трогаем. Из-за него правило фактически действует в диапазоне 400 000 < пробег ≤ 500 000 км — заявки с пробегом > 500 000 км до решения не доходят. — intent §3; подтверждение — OQ-3.
- LOAN-12 (лимит по `ltv_by_age`), БД, фронтенд, сверка пробега по VIN (CASE-08): ожидание из intent — не трогаем, подтверждение перенесено аналитику (OQ-3). — intent §4 п.3.

## 2. Требования

Каждое требование — из intent §1 (замысел); требований сверх intent спека не вводит.

**REQ-MILEAGE-01.** Пробег не больше 400 000 км не влияет на решение по заявке: решение определяется только LTV.
Источник: intent §1 п.1; граница включительно (ровно 400 000 км решение не меняет) — intent §3, ответ в интервью.

**REQ-MILEAGE-02.** Если решение по LTV — approve и пробег больше 400 000 км, финальное решение — review.
Источник: intent §1 п.2, §2.

**REQ-MILEAGE-03.** Если решение по LTV — review и пробег больше 400 000 км, финальное решение — review.
Источник: intent §1 п.2.
Примечание: случай «LTV-reject + пробег > 400 000 км» требованиями не покрывается — открытый вопрос OQ-1, перенесён аналитику.

**REQ-MILEAGE-04.** Если пробег неизвестен (ключ `mileage` отсутствует или равен `null`), заявка отклоняется ошибкой валидации по полю `mileage`; расчёт решения не выполняется.
Источник: intent §1 п.3, §3 (текущее поведение: отсутствие значения — уже ошибка валидации; требование его фиксирует).

**REQ-MILEAGE-05.** Если пробег — пустая строка (`''`), заявка отклоняется ошибкой валидации по полю `mileage`; расчёт решения не выполняется.
Источник: intent §1 п.3 («пробег обязателен: пустое значение — ошибка валидации»); intent §3 (сегодня `''` нормализуется в 0 км и проходит как 0 км — поведение меняется; ответ в интервью — «сделать ошибкой»).

Итоговая матрица решения (пороги LTV — `backend/config/rules.php:44-45`):

| Решение по LTV | Пробег ≤ 400 000 км | Пробег > 400 000 км |
|---|---|---|
| approve (LTV < 60%) | approve — REQ-01 | review — REQ-02 |
| review (60% ≤ LTV ≤ 85%) | review — REQ-01 | review — REQ-03 |
| reject (LTV > 85%) | reject — REQ-01 | не определено — OQ-1 |

## 3. Критерии приёмки

Формат Given / When / Then. Каждое числовое правило проверяется на границе порога (399 999 / 400 000 / 400 001) и при пустом или неизвестном пробеге. Примеры входов: LTV-approve — сумма 450 000 при стоимости 900 000 (LTV 50% < 60); LTV-review — сумма 700 000 при стоимости 900 000 (LTV ≈ 77,78%, в диапазоне 60–85). Источники чисел — раздел 4.

**AC-MILEAGE-01** (REQ-MILEAGE-01).
Given: заявка с решением approve по LTV (450 000 / 900 000) и пробегом 399 999 км.
When: заявка проходит оценку.
Then: решение — `approve`, `approved_limit` = 450 000 (запрошенной сумме) — поведение как до задачи.

**AC-MILEAGE-02** (REQ-MILEAGE-01).
Given: та же заявка, пробег ровно 400 000 км.
When: заявка проходит оценку.
Then: решение — `approve`, `approved_limit` = 450 000 — граница 400 000 км включена, решение не меняется.

**AC-MILEAGE-03** (REQ-MILEAGE-02).
Given: та же заявка, пробег 400 001 км.
When: заявка проходит оценку.
Then: решение — `review` (не `approve`).
Примечание: `approved_limit` при таком понижении AC не фиксирует — открытый вопрос OQ-2, перенесён аналитику.

**AC-MILEAGE-04** (REQ-MILEAGE-03).
Given: заявка с решением review по LTV (700 000 / 900 000) и пробегом 400 001 км.
When: заявка проходит оценку.
Then: решение — `review`.

**AC-MILEAGE-05** (REQ-MILEAGE-04).
Given: заявка с валидными полями, кроме пробега: ключ `mileage` отсутствует или `mileage` = `null`.
When: заявка подана.
Then: ответ — ошибка валидации по полю `mileage` (заявка до расчёта решения не доходит); `decision` и `approved_limit` не возвращаются.

**AC-MILEAGE-06** (REQ-MILEAGE-05).
Given: заявка с валидными полями и `mileage` = `''` (пустая строка).
When: заявка подана.
Then: ответ — ошибка валидации по полю `mileage` (сегодня `''` проходит как 0 км — поведение меняется); `decision` и `approved_limit` не возвращаются.
